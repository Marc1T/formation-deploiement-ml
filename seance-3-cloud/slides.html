Streamlit Community Cloud

Le déploiement garanti : gratuit, sans carte, depuis GitHub.

Streamlit Community Cloud

Comment ça marche

uv export --format requirements-txt --no-default-groups \
  --group app --no-hashes --no-emit-project -o app/requirements.txt

Streamlit Cloud cherche d'abord à côté du fichier principal, puis à la racine, où uv.lock passe avant requirements.txt. Sans app/requirements.txt, il installerait MLflow et DVC.

Les secrets (API_URL, GEMINI_API_KEY) se saisissent dans l'interface, au format TOML, et se lisent avec st.secrets.

Chaque push sur main redéploie : déploiement continu sans rien configurer.

Streamlit Community Cloud

Et le modèle ? Trois options

1 · Mode API

Secret API_URL vers votre API Azure (Lab 9). L'application ne porte aucun modèle.

La plus propre.

2 · Modèle téléchargé

Secret MODEL_URL vers un model.joblib publié (asset d'une release GitHub). On sert exactement l'artefact validé.

★★

3 · Repli de démonstration

Sans modèle, l'application s'entraîne au démarrage sur les données publiques du jeu Pima, avec un avertissement visible.

Pour réussir en séance ; à proscrire en vrai projet.

Le modèle servi doit être un artefact versionné : release, remote DVC, registre MLflow ou image Docker. Jamais réentraîné en silence.

Lab 8 · À retenir

Ce qu'il faut retenir

  • Déployer, c'est rendre explicite ce que votre machine fournissait en silence : dépendances, modèle, configuration.
  • Un fichier de dépendances à côté du fichier principal, généré depuis uv.lock : il prime sur la racine.
  • La configuration vient de l'environnement ou des secrets, jamais du code ; une seule fonction lit les deux.
  • Le repli de démonstration est un filet, pas une méthode : en vrai, on sert un artefact versionné.

Commandes clés

  --no-default-groups --group app \
  --no-hashes --no-emit-project \
  -o app/requirements.txt
git push        # redéploie

Azure · projet fil rouge

Les commandes

$ az login && az extension add --name containerapp --upgrade
$ az group create --name rg-diabetes-ml --location francecentral
$ az containerapp env create --name cae-diabetes-ml --resource-group rg-diabetes-ml --location francecentral
$ az containerapp create --name diabetes-api --resource-group rg-diabetes-ml --environment cae-diabetes-ml \ --image ghcr.io/<vous-en-minuscules>/diabete-lab/api:latest --target-port 8000 --ingress external \ --min-replicas 0 --max-replicas 1 --cpu 0.5 --memory 1.0Gi \ --env-vars THRESHOLD=0.5
$ az containerapp show -n diabetes-api -g rg-diabetes-ml --query properties.configuration.ingress.fqdn -o tsv
diabetes-api.kindhill-1a2b3c4d.francecentral.azurecontainerapps.io
$ curl https://diabetes-api.…azurecontainerapps.io/predict -d '{…}'
{"prediction":1,"probability":0.5838}

Commandes et options vérifiées avec Azure CLI 2.93. Le fil rouge les enchaîne dans deploy/azure/deploy.ps1 (ou .sh).

Azure

Points d'attention

Image privée. Un package ghcr.io est privé par défaut : rendez-le public, ou passez --registry-server ghcr.io --registry-username … --registry-password <PAT>.

Pas de Docker local ? deploy.ps1 -UseAcr construit l'image dans Azure Container Registry avec az acr build.

Journaux : az containerapp logs show -n diabetes-api -g rg-diabetes-ml --follow.

Nettoyage en fin de projet : az group delete --name rg-diabetes-ml --yes --no-wait. Tout disparaît, le crédit est préservé.

Lab 9 · À retenir

Ce qu'il faut retenir

  • Trois objets suffisent : un groupe de ressources, un environnement, une application, et votre image tourne en HTTPS.
  • On déploie une image, on la configure par des variables : jamais une image différente par environnement.
  • Un tag immuable par déploiement (SHA) et des révisions : on sait ce qui tourne, on peut revenir en arrière.
  • Ce qui est créé se paie : min-replicas 0 en démonstration, az group delete en fin de projet.

Commandes clés

  --target-port 8000 --ingress external
az containerapp logs show -n diabetes-api \
  -g rg-diabetes-ml --tail 30
az group delete --name rg-diabetes-ml --yes

Google AI Studio : Gemini dans l'application

Prototyper, créer une clé, la ranger, l'utiliser.

Google AI Studio

De AI Studio à votre application

Palier gratuit : limites de débit par minute et par jour (consultez AI Studio, elles changent), et vos requêtes peuvent servir à améliorer les modèles : pas de données personnelles.

Google AI Studio · projet fil rouge

Le code

GEMINI_API_KEY = setting("GEMINI_API_KEY")            # .env, ou secrets Streamlit
GEMINI_MODEL = setting("GEMINI_MODEL", "gemini-flash-latest")

def explain_with_gemini(values, result):
    from google import genai
    client = genai.Client(api_key=GEMINI_API_KEY)
    prompt = ("Tu es un assistant pédagogique … "
              f"risque estimé {result['probability']:.0%} pour : {values} … "
              "En quatre phrases, en français. Rappelle qu'il s'agit "
              "d'un exercice pédagogique et non d'un avis médical.")
    return client.models.generate_content(model=GEMINI_MODEL, contents=prompt).text

if "result" in st.session_state:                      # le bloc qui affiche le résultat
    …
    if GEMINI_API_KEY and st.button("Expliquer cette estimation"):
        with st.spinner("Gemini rédige…"):
            try:
                st.write(explain_with_gemini(st.session_state["values"], result))
            except Exception as exc:
                st.error(f"Appel Gemini impossible : {exc}")

Le second bouton va dans le bloc du résultat gardé en session_state : placé sous « Estimer », il n'aurait jamais d'effet.

Le try/except transforme clé invalide (400), quota (429) et panne en un message, pas une page blanche. Sans clé, pas de bouton.

google-genai doit figurer dans app/requirements.txt : regénérez-le avant de pousser.

Les secrets

Une seule façon de lire, plusieurs façons de fournir

Une clé commitée est compromise, même supprimée au commit suivant : révoquez-la dans AI Studio et créez-en une autre. git grep AIza avant chaque push.

Lab 11 · À retenir

Ce qu'il faut retenir

  • Prototyper dans AI Studio, appeler par le SDK : le prompt se met au point dans l'interface, puis se copie dans le code.
  • La clé est un secret : .env en local, Secrets sur la plateforme, jamais dans le dépôt ; une clé commitée se révoque.
  • Tout appel à un service externe peut échouer : clé, quota, panne ; l'application le dit et continue.
  • Pas de données personnelles sur l'offre gratuite : Google peut s'en servir pour améliorer ses modèles.
